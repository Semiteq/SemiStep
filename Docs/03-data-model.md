# 3. Модель данных и рецепта

[← Назад к оглавлению](index.md) | [← Пользовательский интерфейс](02-ui-requirements.md)

---

## 3.1. Структура рецепта

- **Рецепт**: упорядоченный список шагов.
- **Каждый шаг** содержит:
  - тип действия;
  - набор параметров (значения по параметрам, определённым конфигурацией);
  - комментарий и служебные поля (при необходимости).

---

## 3.2. Ограничения

| Параметр | Значение |
|----------|----------|
| Максимум шагов | ~1000 |
| Максимум параметров | ~30 |

Конкретный набор параметров и их типы задаются конфигурацией, получаемой из ПЛК.

---

## 3.3. Валидация данных

На основе типов параметров и их ограничений:

- диапазоны значений;
- формат данных;
- обязательность заполнения.

**При вводе недопустимых значений:**

- отображается понятное сообщение;
- запрещается сохранение/отправка рецепта в ПЛК до исправления ошибок.

---

## 3.4. Связанные параметры (inline-формулы)

Действие может объявлять блок `formula:` в конфигурации, описывающий алгебраическую связь нескольких параметров шага (например, для `t°C плавно` соотношение `(task − initial_value) / speed · 60 = step_duration`). Блок содержит:

- `recalc_order` — приоритетный список переменных; цель пересчёта определяется как первая запись `recalc_order`, отличная от только что изменённой переменной;
- `expressions` — словарь явных выражений «как пересчитать данную цель через остальные переменные» (по одному выражению на каждую запись `recalc_order`).

**Поведение при редактировании ячейки:**

- При фиксации правки одной из связанных ячеек выбирается цель пересчёта по правилу выше, и её новое значение вычисляется немедленно в рамках того же шага мутации (`RecipeSession.UpdateStepProperty`).
- Оригинальная правка пользователя и пересчитанное значение образуют **одну запись истории** — `Ctrl+Z` отменяет обе одновременно.
- Если вычисление невозможно (деление на ноль, NaN/Infinity) либо результат выходит за допустимый диапазон параметра, правка **отклоняется целиком**: рецепт остаётся неизменным, причина отказа отображается в панели сообщений (`FormulaComputationFailedError` / `FormulaTargetOutOfRangeError`).
- Действия без блока `formula:` обрабатываются как раньше — связной пересчёт не выполняется.

**Корректность выражений** проверяется на этапе загрузки конфигурации: каждое выражение должно разбираться парсером, ссылаться только на переменные из `recalc_order`, а `recalc_order` обязан перечислять реальные колонки действия. Нарушения сообщаются как ошибки конфигурации и блокируют запуск.

**Ограничения на идентификаторы и типы:**

- Имена переменных в выражениях и в `recalc_order` сравниваются с ключами колонок без учёта регистра, **но** должны точно совпадать по регистру с канонической записью колонки (`columns[].key`). Несоответствие регистра между телом выражения и `recalc_order` сообщается как ошибка конфигурации.
- Все колонки, перечисленные в `recalc_order`, должны иметь числовой `system_type` (`int` либо `float`). Строковые и иные нечисловые типы запрещены и сообщаются как ошибка конфигурации.
- Если результат пересчёта целочисленной цели выходит за пределы Int32 либо результат для `float`-цели после приведения становится `±Infinity`, правка отклоняется как `FormulaComputationFailedError`.

---

## 3.5. Импорт CSV

Импорт рецепта из CSV выполняется **дословно**: значения ячеек загружаются как есть, **inline-формулы при импорте не вычисляются** и не используются для проверки внутренней согласованности файла. Автор CSV-файла отвечает за то, чтобы значения связанных параметров удовлетворяли формуле. Открытие рецепта, созданного во внешнем инструменте, не должно молчаливо изменять данные пользователя.
